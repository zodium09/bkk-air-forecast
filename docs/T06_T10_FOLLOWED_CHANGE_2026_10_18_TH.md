# T06/T10 · การเปลี่ยนแปลงของสถานีที่ติดตาม (18 ต.ค. 2569)

## พฤติกรรมที่เพิ่มแล้วใน working tree

- หน้า `/` มีส่วน “สถานีที่คุณติดตาม” และ `/watchlist` ใช้รายการเดียวกัน เรียงสถานีที่ feed หายหรือค่าล่าช้าก่อน แล้วเรียงสถานีที่มีระดับน้ำเพิ่มมากสุดจากค่าก่อนหน้า แสดงได้สูงสุด 5 สถานีบนหน้าแรก และทั้งหมดบนหน้า watchlist
- อ่านประวัติจริงเฉพาะสถานีที่บันทึกไว้ในเครื่อง ไม่อ่านประวัติทั้งลุ่มเพื่อเดาแนวโน้ม สรุปการเปลี่ยนแปลงเป็นเซนติเมตรเมื่อค่าล่าสุดของ archive **ตรงทั้งเวลาและค่าปัจจุบัน** สถานียังสด (ไม่เกิน 60 นาที) และค่าก่อนหน้าห่าง 5–120 นาที ใช้ datum ของสถานีเดียวกัน ไม่เฉลี่ยหรือประมาณระหว่างสถานี
- หากไม่มีค่าก่อนหน้าที่เทียบได้, archive ไม่พร้อม, คำขออ่านล้มเหลว, ค่าล่าช้า หรือสถานีไม่อยู่ใน feed ล่าสุด แสดงเหตุผลแยกกัน รหัสสถานีที่หายจาก feed ยังคงอยู่ใน watchlist เพื่อกลับมาตรวจได้
- จำกัดสถานีใหม่ใน watchlist 20 แห่งและอ่านประวัติเป็นชุดละ 4 คำขอ หน้าที่มีรายการเดิมมากกว่า 20 แห่งยังแสดงทุกรายการ แต่ตรวจแนวโน้ม 20 รายการแรก การอ่านซ้ำเกิดเมื่อค่าตรวจวัดของสถานีที่ติดตามเปลี่ยนหรือผู้ใช้กดอัปเดต ไม่ยิงซ้ำทุกนาทีเพียงเพราะนาฬิกาหน้าเว็บเดิน

## ข้อจำกัดและงาน Sol ต่อ

- นี่คือการเปลี่ยนแปลง **ของสถานีที่ผู้ใช้เลือก** ไม่ใช่แนวโน้มน้ำทั้งลุ่มหรือคำพยากรณ์น้ำท่วม หน้าแรกยังต้องเพิ่มสรุปช่องว่างที่กระทบการอ่านทั้งลุ่มให้เด่นขึ้น และทดสอบว่าเนื้อหาสำคัญอยู่ในจอแรกที่ 390×844 จริง
- Site ที่เผยแพร่อยู่อ่านแบบ read-only วันที่ 18 ต.ค. แล้วยังไม่มี D1 binding (`bindings: []`, `tables: []`) จึงยังไม่ยืนยันประวัติถาวรหรือ scheduler production ตาม Gate A/B ห้ามอ้างว่าแนวโน้มพร้อมใช้งานทั่วระบบจน provision และตรวจรอบเก็บจริง
- ต้องทำ station master catalog เพื่อให้ ID ที่ feed เลิกส่งยังมีชื่อ/พื้นที่/หน่วยเก่าอย่างถูกต้อง ตอนนี้ fallback แสดงรหัสกับคำอธิบาย แต่ยังไม่มี metadata คงทน
- ต้องตรวจด้วยเบราว์เซอร์จริงที่ 320/390/768 px, 200% text zoom, keyboard/screen reader, ค่าประวัติว่าง/แก้ย้อนหลัง/feed หาย และต้นทางล้ม ก่อนผ่าน Gate D รอบ 18 ต.ค. เครื่องมือเบราว์เซอร์ปฏิเสธการเข้าถึง local URL ด้วย URL policy จึงมีเพียงผล build/test และการตรวจโค้ด ยังไม่อ้างว่า QA ภาพจริงผ่าน

## หลักฐานตรวจ

`npm run lint`, `npx tsc --noEmit` (หลัง `npx next typegen` เพื่อแก้ไฟล์ route types ที่ Cloudflare build สร้างทับ), `npm test` (unit 256/256 และ rendered 34/34), `npm run build -- --webpack` ผ่าน การทดสอบใหม่ยืนยัน current/archive mismatch, missing history, stale, gap มากกว่า 2 ชั่วโมง และ sample ถี่เกินกว่าจะตีความเป็นการเปลี่ยนแปลงตามช่วงที่ตั้งไว้
