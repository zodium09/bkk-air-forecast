# สัญญาเนื้อหา · เจ้าพระยา ฝนและน้ำ

สถานะ: ใช้กำกับหน้ารุ่นใหม่ที่ `/`, `/explore`, `/basins/[id]`, `/stations/[id]`, `/watchlist`, `/sources` ตั้งแต่ 15 ตุลาคม 2569 ส่วนหน้า `/rain`, `/water`, `/air`, `/heat` ยังเป็นเส้นทางเดิมระหว่างการย้าย

## งานของผู้ใช้และลำดับคำตอบ

ผู้ใช้หลักติดตามฝน น้ำท่วมที่มีหลักฐาน และสถานการณ์ลุ่มน้ำ ถามว่า **ที่ไหนมีค่าล่าสุดอะไร เปลี่ยนอย่างไร ข้อมูลพอให้สรุปหรือไม่ และเปิดต้นทางตรงไหน** หน้าแรกตอบระดับทั้งระบบและรายลุ่มน้ำก่อน; หน้าเชิงลึกเปิดตำแหน่งสถานีและกราฟ; หน้าสถานีแสดงตัวตน datum เวลา เกณฑ์ และคุณภาพก่อนอธิบายผล ไม่บังคับอนุญาตตำแหน่ง

โหมดสรุปและเชิงลึกใช้ `buildHydroBasins` กับ source payload เดียวกัน โหมดเป็นรูปแบบการอ่าน ไม่เปลี่ยนค่าหรือเกณฑ์ ขอบเขตที่แสดงคือปิง 06, วัง 07, ยม 08, น่าน 09, สะแกกรัง 11, ป่าสัก 12 และเจ้าพระยาตอนกลาง–ล่าง ขอบเขตย่อยใช้รูปหลายเหลี่ยม DWR ฉบับที่บันทึกใน repository; สถานีหนึ่งจุดไม่ถูกนับซ้ำระหว่างลุ่มย่อยกับส่วนกลาง

## คำที่ใช้

| คำ | ความหมายที่อนุญาต | ห้ามตีความเป็น |
|---|---|---|
| สถานีน้ำล่าสุด | ค่าตรวจวัดอายุไม่เกิน 60 นาทีตามเวลาแหล่งข้อมูล | ทั้งพื้นที่ปลอดภัยหรือได้ตรวจครบทุกสถานี |
| น้ำมาก | ความจุลำน้ำ >70–100% ตามเกณฑ์ต้นทาง ณ สถานีสด | น้ำท่วม/ถึงตลิ่งทุกจุด |
| เกินเกณฑ์สถานี | ความจุลำน้ำ >100% หรือค่า รทก. เทียบตลิ่งใน datum เดียวกันแล้วถึง/เกิน | แผนที่พื้นที่ท่วมหรือประกาศทางการ |
| ฝนสะสม 24 ชม. สูงสุดในสถานี | ค่าสูงสุดของสถานีที่รายงานภายใน 3 ชั่วโมง | ฝนเฉลี่ยทั้งลุ่มหรือโอกาสฝน |
| อ่างรายวัน | รายงานวันที่ต้นทางระบุ ปริมาตรเข้า/ระบายเป็นล้าน ลบ.ม. ในวันนั้น | อัตราการไหลวินาทีหรือข้อมูลสดรายนาที |
| ไม่มีข้อมูล / ไม่ครอบคลุม | ไม่มีค่าที่ผ่านเงื่อนไขหรือไม่มี feed สำหรับส่วนนี้ | ศูนย์ ปกติ หรือไม่มีเหตุการณ์ |
| เวลารับข้อมูล | เวลาแอปรับ payload | เวลาตรวจวัดทุกสถานี |
| เรดาร์ตรวจจริง | ภาพประมาณอัตราฝน มม./ชม. ณ เวลาภาพ; ใช้ได้เมื่ออายุไม่เกิน 90 นาที | ฝนสะสมสถานีหรือภาพปัจจุบันเมื่อหมดอายุ |
| เรดาร์คาดการณ์ระยะสั้น | ภาพที่มีเวลาใช้ได้ในอนาคตจากฐานภาพล่าสุด; ปิดเมื่อฐานเกิน 30 นาที | ภาพตรวจจริงหรือคำทำนายเวลาฝนถึงบ้าน |
| พยากรณ์ฝนจังหวัด | ยอดสะสมแบบจำลองเฉลี่ยจุดตัวอย่างที่มีข้อมูลในจังหวัด/ส่วนในลุ่มที่เลือก รายวันหรือช่วง 3 ชม.; เวลาแสดงคือเวลาที่ดึงข้อมูล | ฝนตรวจวัด ทั้งลุ่ม 7 ลุ่ม หรือเวลาที่หน่วยงานออกพยากรณ์ |
| น้ำขึ้นน้ำลงทำนาย | ค่าสูงสุด/ต่ำสุดตามตารางรายชั่วโมงของสถานีปลายน้ำที่เลือก หน่วย ม. รทก. | ระดับน้ำตรวจวัด การหนุนย้อนถึงสถานีอื่น หรือพยากรณ์น้ำท่วม |

ระดับน้ำ รทก. กับระดับจากศูนย์เกจห้ามเทียบข้าม datum โดยตรง ค่าระดับน้ำไม่ใช่ความลึกน้ำท่วม หากเวลาเก่ากว่า 60 นาทีต้องไม่สร้างสัญญาณปัจจุบัน; อายุเกิน 24 ชั่วโมงไม่แสดงตัวเลขเป็นค่าปัจจุบัน ค่า 0 ที่ต้นทางยืนยันต่างจากค่าว่าง

## หลักฐานและกรณีข้อมูลขาด

ทุก station detail แสดงชื่อทางน้ำ หน่วยงาน เวลา datum เกณฑ์ที่มี และลิงก์ ThaiWater ประวัติเป็นค่าที่ระบบสะสมจริง; ไม่มีจุดย้อนหลังให้บอกว่ารอสะสม ไม่ลากเส้นเติมช่องว่าง และข้อมูลสดต้องอ่านได้แม้คลังประวัติล้ม หน้าข้อมูลระบุ coverage แต่ละลุ่ม แหล่งที่ตอบกลับและความถี่จริง ข้อความ “ต้นทางตอบกลับ” ไม่ใช่ “ทุกสถานีมีค่าล่าสุด”

ฝนตรวจวัดส่วนกลางใช้เฉพาะสถานี ThaiWater รหัสลุ่มน้ำ 10 ที่อยู่ใน polygon เจ้าพระยาแท้ของ DWR; ไม่รวมพื้นที่มหานครที่อยู่นอกลุ่มน้ำ หากไม่มีค่าล่าสุดให้แสดงช่องว่าง ไม่ใช้ค่าพยากรณ์เติมตำแหน่งของ observation หากต้นทางล่ม ระบบอ่าน snapshot ที่เก็บไว้แยกแหล่งและติดป้าย “ใช้ข้อมูลที่เก็บไว้”; ความสดของฝน น้ำ และอ่างคำนวณใหม่จากเวลาจริง ไม่ต่ออายุ snapshot ให้เป็นข้อมูลสด พยากรณ์จังหวัดชุดปัจจุบันครอบคลุมเฉพาะจังหวัดตอนกลาง–ล่างที่มีขอบเขตและจุดตัวอย่างในแอป หน้าเริ่มต้นของลุ่มต้นน้ำจึงแสดงช่องว่างแทนค่าที่ไม่ตรงพื้นที่ หน้ารุ่นใหม่ยังไม่มีประกาศทางการ การติดตามเหตุ/พื้นที่ท่วมที่ยืนยัน และการคาดเวลาเดินทางของน้ำ จึงไม่ใช้คำว่า “แจ้งเตือนภัย” หรือ “น้ำจะถึง”

## ขอบเขตการตรวจรับที่ยังค้าง

การเก็บประวัติและ snapshot แบบ D1 มี scheduled collector ใน Cloudflare Worker แต่ต้องพิสูจน์รอบเก็บและ persistence ใน runtime ที่เผยแพร่จริง; file store เป็นเพียงการพัฒนาในเครื่อง ก่อนใช้ snapshot และ revision ใน production ต้องใช้ migration ที่บันทึกใน Drizzle journal `drizzle/0001_productive_daredevil.sql` หลัง `0000` และ backfill แยกเฉพาะฐานเก่าที่มี observation มี revision journal และ `/api/ingestion-health` แล้ว แต่หน้าสถานะในเครื่องที่ยังไม่มีรอบเก็บจะแสดงว่าไม่ทราบสถานะ ไม่กล่าวว่าระบบ production ทำงาน การเทียบหลายสถานีและฝน/เรดาร์/พยากรณ์/น้ำทำนายใน shell ใหม่ทำระดับต้นแล้ว แต่ยังต้อง QA มือถือ/การเข้าถึง, ตรวจ coverage พยากรณ์ต้นน้ำ, source fallback และซูม 200% ก่อน Gate D ห้ามอ้างว่าเสร็จเพราะหน้าใหม่แสดงได้
